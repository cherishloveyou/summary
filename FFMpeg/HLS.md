## HLS

HTTP Live Streaming: HLS是一个由苹果公司提出的基于HTTP的流媒体网络传输协议，可以实现流媒体的直播（live）和点播(vod)。

HLS协议规定：HLS协议由**HTTP+M3U8+TS**三部分组成，HTTP是传输协议，M3U8是索引文件，TS是视音频的媒体信息。 视频的编码格式为H264,音频编码格式为MP3、AAC或者AC-3。

工作原理：把整个ts流分成一个个ts小文件供播放器按顺序下载播放。在开始一个流媒体会话时，客户端会下载一个包含元数据的extended M3U (m3u8) playlist文件，用于寻找可用的媒体流。

HLS 的工作原理可以分为以下几个主要步骤：

1. **准备媒体文件**：

   将原始视频文件（如 MP4）编码为多种不同的比特率和分辨率。这使得客户端能够根据当前网络条件选择最合适的流。

2. **分片**：

   将编码后的视频文件切割成若干小的时间段（segment），每段通常为 2-10 秒。每个小片段通常以 TS（MPEG-2 Transport Stream）格式保存。

3. **生成播放列表**：

   创建一个 M3U8 格式的播放列表文件（.m3u8），该文件包含了各个小段的URI以及不同质量流的选定信息。M3U8 文件中还会包含流的编码信息及相关元数据。

4. **客户端请求**：

   客户端（如浏览器或移动应用）请求 M3U8 播放列表文件。通过解析该播放列表，它能够获取可用的流信息并根据网络状况选择相应的片段。

5. **播放流**：

   客户端开始下载和播放 M3U8 列表中指定的 TS 段。它可以根据当前的网络条件动态调整下载的比特率（即选择较低或较高质量的片段）。

6. **自适应比特率**：

   在播放过程中，客户端持续监测网络带宽。当它检测到网络条件变差时，可以切换到较低比特率的流，以避免缓冲；网络条件改善时，则可以切换回较高比特率的流。

##### 优势：

###### 1.码率自适应（Adaptive Streaming）

HLS支持自适应比特率流（ABR) 当媒体流正在播放时根据用户的网络状况，播放器可以动态调整视频质量，从而优化播放体验，减少缓冲和停顿。

###### 2.基于HTTP(穿墙/性能高)

HLS采取HTTP协议传输文件,使用标准Web服务器，所以可以穿过任何允许HTTP数据通过的防火墙或者代理服务器。相比之下，因为RTMP协议不使用标准的HTTP接口传输数据，所以在一些特殊的网络环境下可能被防火墙屏蔽掉。

###### 3.跨平台性：

支持PC/Android/IOS平台，并在移动端趋势明显。（PC主要的直播方案是RTMP）

###### 4.充分利用CDN（负载均衡）：

CDN即Content Delivery Network （内容分发网络）。CDN包含两大核心技术：负载均衡和分发网络
于负载，RTMP是一种有状态协议，很难对视频服务器进行平滑扩展，因为需要为每一个播放视频流的客户端维护状态。而HLS基于无状态协议（HTTP），客户端只是按照顺序使用下载存储在服务器的普通TS文件，做负责均衡如同普通的HTTP文件服务器的负载均衡一样简单。

###### **渐进式播放**：

- HLS允许用户在视频完全下载之前开始播放，这样可以明显提高用户的观看体验。

###### **支持加密和 DRM**：

- HLS支持通过AES加密保护流媒体内容，同时可与数字版权管理（DRM）系统配合使用，以防止未经授权的访问。

###### **分片和索引**：

- HLS将视频流分为小片段（通常为6到10秒），这使得网络传输更加高效。同时，播放列表文件（M3U8）提供了对视频片段的索引，使播放器能够灵活处理播放和切换。

  

##### 劣势：

###### 1.实时性差：

基本上HLS的延迟在10秒以上,而RTMP协议的延迟最低可以到3、4秒左右。

###### 2.文件碎片：

若分发HLS，码流低，切片较小时，小文件分发不是很友好。特别是一些对存储比较敏感的情况，譬如源站的存储，嵌入式的SD卡。

HLS延时分析
HLS理论上延时=1个切片的时长+ 0-1个td + 0-n个启动切片 +网络连接耗时。

td是EXT-X-TARGETDURATION，可简单理解为播放器取片的间隔时间
n:苹果官方建议是请求到3个片之后才开始播放

为了追求低延时效果，我们可以将切片切的更小，取片间隔做的更小，播放器未取到3个片就启动播放。极致来说可以缩减列表长度为1，并且 ts 的时长为1s，但是这样会造成请求次数增加，增大服务器压力，当网速慢时回造成更多的缓冲，增加HLS不稳定和出现错误的风险。

5. **HLS 中的 key frame（关键帧）是什么？**
   - 解释关键帧的概念及其在 HLS 流中的重要性。
     1. **流畅性与用户体验**：
        - HLS流通常由多个小片段（如TS文件）组成，每个片段的起点通常是一个关键帧。这保证了在播放开始或用户拖动进度时，播放器可以快速找到关键帧，从而减少缓冲时间，提升用户体验。
     2. **随机访问**：
        - 关键帧提供了视频的随机访问点。例如，如果用户希望跳转到视频的某一点，播放器可以迅速找到最近的关键帧，避免从视频流的开头开始解析，从而减少加载时间。
     3. **自适应码率流**：
        - 在HLS的自适应比特率流中，不同清晰度的视频流通常也会以关键帧为起点进行编码。这使得在切换流时，可以低延迟地平滑过渡，确保播放顺畅，不会影响观看体验。
     4. **错误恢复**：
        - 在网络不稳定或错误的情况下，关键帧也起到一定的恢复作用。播放器可以在失去数据后从最近的关键帧重新开始播放，这极大地提高了流媒体的鲁棒性。
     5. **提高编码效率**：
        - 适当设置关键帧的间隔可以帮助在保持视频质量的同时有效压缩视频数据。对于实时应用（如直播），确保关键帧的合理间隔至关重要，以应对延迟和加速播放的需求。

4. **如何优化 HLS 流媒体的加载时间？**

   - 讨论减少加载时间的最佳实践和优化策略。

     ###### 1. **合理设置分段长度**

     - **短分段**：将视频分段设置为较短的时长（如6秒或更少），可以加快用户开始播放的速度，因为播放器可以更快地加载第一个分段。
     - **目标持续时间**：在`#EXT-X-TARGETDURATION`中设置合理的目标持续时间，确保它与实际片段长度相匹配。

     ###### 2. **使用关键帧**

     - 确保每个分段的开头都是关键帧，这样播放器可以快速找到播放起点，减少加载时间。
     - 关键帧间隔应适当设置，以确保流畅的播放体验。

     ###### 3. **自适应比特率流**

     - 提供多种码率和分辨率的流，以便播放器根据用户的网络条件动态选择合适的流。确保播放列表中的不同流版本具有相似的关键帧时间戳，以便于流的切换。

     ###### 4. **优化服务器性能**

     - **使用CDN（内容分发网络）**：将视频内容分布到多个地理位置的服务器上，以减少用户与服务器之间的延迟。
     - **HTTP/2支持**：确保服务器支持HTTP/2协议，可以提高并发请求的处理能力，减少延迟。

     ###### 5. **减少HTTP请求**

     - 合并小文件：如果可能，减少小的片段数量，合并文件可以减少HTTP请求的数量。
     - 使用适当的缓存策略：设置HTTP缓存头，允许播放器在一定时间内缓存分段，避免重复下载。

5. **描述 HLS 中的 m3u8 文件结构。**

   - 请简要说明 m3u8 文件的内容结构及其解析方式。

1. **文件头**：

   - 文件的开始部分通常以`#EXTM3U`表示，表明这是一个扩展的M3U格式文件。

   ```
   m3u8
   #EXTM3U  
   ```

2. **播放列表条目**：

   - 使用以`#EXT-X-`开头的指令来描述视频流和段的信息。以下是一些常用的指令：

#### 常见的指令

- **#EXT-X-VERSION**：

  - 指定使用的HLS协议版本。

  ```
  m3u8
  #EXT-X-VERSION:3  
  ```

- **#EXT-X-TARGETDURATION**：

  - 指定每个视频片段的最大持续时间（以秒为单位）。

  ```
  m3u8
  #EXT-X-TARGETDURATION:10  
  ```

- **#EXT-X-MEDIA-SEQUENCE**：

  - 指定第一个媒体分段的序号，帮助播放器在读取片段时保持正确顺序。

  ```
  m3u8
  #EXT-X-MEDIA-SEQUENCE:0  
  ```

- **#EXTINF**：

  - 每个分段的持续时间和选项，后面通常跟着分段的URI。格式如下：

  ```
  m3u8
  #EXTINF:10.0,  
  segment1.ts  
  ```

- **#EXT-X-ENDLIST**：

  - 指明这是一个结束播放列表的标记，表示流的结束。

  ```
  m3u8
  #EXT-X-ENDLIST  
  ```

#### 示例 m3u8 文件

以下是一个包含几个分段的简单m3u8文件示例：

```
m3u8
#EXTM3U  
#EXT-X-VERSION:3  
#EXT-X-TARGETDURATION:10  
#EXT-X-MEDIA-SEQUENCE:0  

#EXTINF:10.0,  
segment0.ts  
#EXTINF:10.0,  
segment1.ts  
#EXTINF:10.0,  
segment2.ts  
#EXTINF:10.0,  
segment3.ts  
#EXTINF:10.0,  
segment4.ts  

#EXT-X-ENDLIST  
```
